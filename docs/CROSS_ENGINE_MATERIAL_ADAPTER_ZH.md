# 跨引擎材质表征与参数适配

当前结论：现有单引擎训练框架不能自动解决跨引擎参数等价问题。此轮新增了参数域隔离、专属头原型和匹配响应约束；尚未完成多引擎训练、标定映射或真实视频效果验证。新数据不直接混进原参数标签。

## 为什么不能直接拼 GT

单位相同、参数同名，仍不保证行为等价：本构模型、应力/应变定义、阻尼、时间积分、接触、网格/粒子分辨率都可能改变响应。弹簧刚度 N/m 不能直接当作杨氏模量 Pa；外观材质类别也不能当作连续参数真值。

本轮有实测例子。A800 安装的 pyuipc 0.0.29 在 E=1 MPa、ν=0.3 时写入的能量系数为 μ=512820.51 Pa、λ=897435.90 Pa。上游当前 SNK1 文档要求 μ=384615.38 Pa、λ=961538.46 Pa。两者并非同一参数映射。原生粗/细梁位移相对解析解误差约 70.8% / 44.7%；显式改用当前物理映射并加密网格后，细网格误差降至约 3.06%。该改善同时改变了映射和分辨率，不能把全部改善归因于某一个因素。

参考：[官方 SNK1 公式与材料输入说明](https://github.com/spiriMirror/libuipc/blob/main/docs/specification/constitutions/stable_neo_hookean.md)，实测：[原生梁](UIPC_BEAM_CALIBRATION.json)、[修正梁](UIPC_BEAM_CORRECTED_CALIBRATION.json)。文档对应上游当前源码，不能据此假定发布轮子已经包含其改动。未来生成数据必须显式记录实际系数，不能只记录 E/ν 和包名。

随后完成了同 E/ν、几何、载荷、边界下的 2×2 析因对照：[映射 × 网格结果](UIPC_MAPPING_GRID_ABLATION.json)。20×4×4 网格时，原生/修正误差为 44.65% / 32.46%；80×16×16 时为 21.73% / 3.06%。固定网格单独修正系数使位移增加约 22.0% / 23.9%；因此材料映射和网格误差确实都存在，不能靠一个统一缩放因子解决所有场景。

## 拟采用的学习结构

视频 / 几何 / 交互信息 → 共享场及响应表征 z → 两类输出：

1. 共同响应描述：标准加载下的柔顺性曲线、压缩/剪切响应、松弛/回弹、耗散、屈服后的残余形变等。描述必须带测试协议、适用应变/速率范围与可见性 mask，不要求所有数据集都有全部观测。
2. 引擎专属参数头：输入 z，输出对应引擎和本构所需的原生参数，例如 FEM 的 E/ν/ρ、弹簧网络的刚度/阻尼。每个域单独统计、编码和损失；不共享同名 GT 的标准化器。

引擎域至少包含 engine、version、constitutive_law、coefficient_mapping、solver_protocol、parameter_units。solver_protocol 应固定积分/接触/分辨率方案；网格未收敛时，其拟合参数只是该数值配置下的有效参数。

引擎 ID 只选择原生参数头，不输入共同响应头；这只是结构约束，**不能保证 z 已经引擎无关**。需要进一步用相同标准物体/加载下的跨引擎成对响应监督、真实交互响应监督和留一引擎评估约束它。新引擎必须先校准一个 adapter；不能零样本声称知道它的参数语义。

目标函数拟分为：域内原生参数的 mask 损失 + 匹配协议的响应预测/对齐损失 + 匹配条件下的相对响应损失 + 场预测损失。各项先独立检验，避免未经校准的 response loss 再次造成负迁移。数据集仅提供 RGB/轨迹时，只参与其支持的监督，缺失参数不填伪 GT。

## 相对特性是否有用

有用，但不能把“材质”简化成一个全局软硬标量。海绵、橡胶和布在拉伸、压缩、剪切、大变形及不同速率下可能呈现不同排序。质量/密度也不能从静态柔软程度推出。

优先比较同几何、尺度、载荷、边界、观测定义和工作区间下的响应：例如固定 10% 压缩时的割线刚度，或小应变下的切线柔顺性。可以在同一协议内预测 log 响应比，并用测量/仿真误差设定“近似相同”的区间，不强迫噪声样本严格排序。

本轮修正梁在 E 加倍时位移比约 2，说明该测试条件内相对刚度关系正确；这不是不同形状真实物体的全局材质排序证据。跨数据集若缺载荷、尺度或边界，保留为域内相对先验或视觉/运动预训练，不能用于强等价约束。

## 已落地与待落地

- `fieldbridge.engine_domains.EngineDomain`：明确原生参数语义域；同参数不同系数映射产生不同域。
- 原 `read_manifest` / `fit_stats` / 数据加载链路：单参数头遇到多个显式域，或未标注的多个来源标签时立即拒绝，避免静默混合 GT。旧单一来源继续按 legacy 处理，不宣称完成物理标定。
- `EngineConditionedHeads`：共享响应头 + 多个原生参数头的独立原型；异构 batch 分组路由；训练集归一化来源、单位/版本/系数及参数 schema 写进检查点并校验；拒绝未知引擎。
- `require_matched_response`：缺失或不同几何/载荷/尺度/边界/观测/单位时拒绝直接相对监督。协议哈希必须覆盖应变、速率、温度及提取约定。

这些原型已加入自动测试，但**尚未接入现有 LocalResidualModel 和训练器，也没有实际训练出通用材质表征**。下一步先做 2 引擎 × 同几何 × 多 E/ν × 多载荷的受控响应矩阵，再接双域训练；仅凭共享头结构不能认定问题已解决。

## 验收顺序

1. 在固定几何和动作下，比较原生参数直接拼接、引擎条件头、响应对齐头，均保留无场等容量控制。
2. 已见引擎：未见物体/加载；报告参数误差与指定仿真器新动作重放误差，分引擎报告。
3. 未见引擎：固定少量校准场景，只训练 adapter，冻结视频/场编码器；比较所需标定量及重放质量。
4. 真实视频：区分无载荷的先验估计与已知交互的拟合；输出可辨识参数、等效范围或不确定性，避免给欠定问题虚假的精确数字。

公开来源采用 [Deform360](https://huggingface.co/datasets/brownu/deform360) 的真实运动数据与 [PhysTwin](https://huggingface.co/datasets/Jianghanxiao/PhysTwin) 的响应/在线拟合场景；已下载的少量元数据不足以确认全部标签语义，仍需逐项适配。PokeFlex 的物体等效刚度也不能当作 E，见[官方数据说明](https://pokeflex-dataset.github.io/)。
