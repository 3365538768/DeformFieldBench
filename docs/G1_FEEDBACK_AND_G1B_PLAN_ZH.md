# G1 反馈与 G1b 执行方案

2026-11-07，G1 六组均完成，均因联合验证指标连续 4 轮无实质改善而早停。以下是固定 512 train / 128 val、seed 17、冻结 DINOv2-S 的诊断；val 为 10 个隔离物体，测试集未使用。

| 方法 | 最佳联合验证标准化 MAE ↓ |
|---|---:|
| B：仅 RGB | 0.79995 |
| C：辅助场监督、无反馈 | 0.83721 |
| D：预测场反馈 | 0.83046 |
| G：等容量特征反馈 | 0.83194 |
| O：真场输入（特权诊断） | 0.73347 |
| S：跨物体置乱真场 | 0.83651 |

D 相对 C 改善 0.81%，但比 B 差 3.81%；O 比 B 改善 8.31%。真场有效，当前预测场桥未优于强无桥基线。按物体的配对 bootstrap，D−B 的 95% 区间为 [-0.00574, 0.06042]，D−C 为 [-0.01643, 0.01324]，均跨零。O−B 为 [-0.11096, -0.00728]。这些是在最佳验证轮次上作出的诊断，存在模型选择影响，不能解释成独立测试显著性。

## 新发现与优先级

`G1_PREDICTED_FIELD_AUDIT.json` 使用 D 的最佳材质检查点，仅在 val 审计，常量基线只拟合 64 个训练样本：

- 接触有效像素正例占 0.818%；预测 IoU 1.734%、召回 1.739%、精度 86.27%。模型主要漏检接触支持。
- 前景视觉流场 MAE 0.13517，对比训练常量 0.14599，改善 7.41%。
- 前景视觉应力图 MAE 0.17808，对比训练常量 0.19870，改善 10.38%。
- 上述字段是旧数据的彩色编码；不是 SI 力、速度或应力。场监督负迁移、接触稀疏和过度聚合均是候选问题，尚未证明单一原因。

因此先修复场监督与反馈梯度，再决定局部时序桥和更强骨干。暂缓原 giant C/D 全量训练；真场组不能作为部署模型。

## G1b：已启动的九组受控诊断

所有组保留 G1 的数据清单、冻结骨干、初始化 seed、batch、优化器、训练预算和验证方式，不从 G1 检查点微调。仅更改明确列出的因素及字节一致的缓存位置。

| 组 | 反馈 | 场权重 | 接触损失 | 目的 |
|---|---|---:|---|---|
| B_rgb_repeat | 无 | 0 | BCE | RGB 复跑及缓存迁移一致性检查 |
| C_weight01 | 无 | 0.1 | BCE | 降低辅助任务权重 |
| D_weight01 | 预测场 | 0.1 | BCE | 与 C、G 匹配的场桥 |
| G_weight01 | 等容量特征 | 0.1 | BCE | 排除额外容量解释 |
| C_weight001 | 无 | 0.01 | BCE | 更弱辅助监督 |
| D_weight001 | 预测场 | 0.01 | BCE | 与 C_weight001 匹配 |
| D_weight01_detached | 预测场，反馈输入截断梯度 | 0.1 | BCE | 检查参数梯度是否干扰场预测 |
| C_weight01_balanced | 无 | 0.1 | 正负类平衡 BCE | 稀疏接触支持对照 |
| D_weight01_balanced | 预测场 | 0.1 | 正负类平衡 BCE | 检查接触修复是否改善材质预测 |

最多 4 GPU 并行，其余自动排队；最长 24 epochs，前 2 epochs 为场预热。联合阶段至少观察 6 轮，连续 4 轮未达到 0.2% 相对改善即早停。网页支持整条队列和单组暂停/继续，完成或早停的组不能通过“继续”偷偷追加预算。

反馈节点：

1. 前两轮检查有限损失、样本覆盖、缓存来源及实际耗时，避免无效长训。
2. 九组完成后自动生成 `docs/G1B_RESULTS.json`，展示匹配 C 控制、RGB 控制及特征控制比较。部分运行的最低分只显示为暂时最佳。
3. 候选需至少比强 RGB 和匹配控制改善 2%，才进入后续路由审查；这是预算路由阈值，不是统计显著性。0.01/平衡损失若胜出，先补齐对应 G 特征控制，再重复独立种子。通过已有匹配控制的候选也必须重复独立种子。
4. 若无收益，转向场预测可拟合性诊断、局部时序桥和度量场数据；不得自动恢复旧 giant 模型继续堆预算。G1b 本身不自动启动全量训练。
5. G2 的实际引擎标定与新动作响应仍是必要验收；当前尚未证明接近在线仿真拟合。

## 数据读取优化与复现

G1 D 后期每轮训练约 29.8 秒，其中 data wait 约 26.9 秒；连同验证与保存约 37.6 秒。16 文件顺序暖读取探针中，AFS 中位数约 0.708 秒，本地临时盘约 0.088 秒；这是读取测试，不是端到端训练加速。

将 640 个已有缓存文件（15,455,804,160 bytes，约 14.4 GiB）复制至 `/tmp/linrui_fieldbridge/g1_dinos16`，全部逐文件 SHA256 校验，原 AFS 缓存保留。相对入口 `data/prepared/g1_dinos16_local` 指向本地副本。迁移用时约 23.8 秒，详见 `G1B_LOCAL_CACHE.json`。G1b 早期一轮训练/验证/保存约 15.5 秒；实际收益需以 RGB 同配置复跑的匹配轮次核对。

RGB 匹配复跑已完成：13 轮验证 MAE 全部一致，最佳轮次 128 条预测的最大标准化差值为 0。排除第一轮后，整轮耗时中位数 31.54 → 17.97 秒（1.75×），训练耗时 24.74 → 13.83 秒，data wait 22.24 → 11.31 秒。详见 `G1B_CACHE_VALIDATION.json`；两次并发与系统条件不同，这是实测收益，不能当成严格硬件基准。剩余数据等待仍占大头，后续应单独 profile 反序列化和 worker 生命周期。

工程验收：A800 完整测试集 21 项通过，前端 JavaScript 语法检查通过；G1b 新组网页暂停/继续请求已实际验证。Linux 队列与缓存链接测试在 Windows 跳过，CPU 模型/训练测试继续保持独立。

在已具备 G1 清单、权重及缓存的 A800 项目根目录：

```bash
python scripts/stage_feature_cache.py \
  --source data/prepared/g1_dinos16 \
  --destination /tmp/linrui_fieldbridge/g1_dinos16 \
  --link data/prepared/g1_dinos16_local \
  --receipt docs/G1B_LOCAL_CACHE.json
python scripts/setup_g1b.py --register
# 已有管理器需要重载，不能同时启动两个管理器；文件锁拒绝重复实例。
python scripts/optimization_manager.py
```

`/tmp` 可能被节点清理，副本缺失时重新执行迁移脚本。新克隆可只执行 `setup_g1b.py` 生成配置；`--register` 要求完整 G1 回执和现有队列计划。单独训练可用 `python -m fieldbridge.train --config configs/g1b_D_weight01_seed17.json`，不依赖队列管理器。
