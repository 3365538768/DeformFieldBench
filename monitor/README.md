# A800 实验观测台

运行 `start.ps1`，然后打开 **http://127.0.0.1:8765**。只依赖 Python 标准库和 Windows OpenSSH，复用本机 `ssh a800` 的配置与密钥。启动器默认使用 Codex 已安装的 Python；也可以手动运行：

```powershell
python server.py --port 8765 --interval 15
```

页面每 5 秒同步本地缓存，后台每 15 秒通过 SSH 采集一次；服务仅监听本机 127.0.0.1。2026-11-07 起支持远端优化队列、阶段反馈以及注册实验的暂停与继续。

当前默认 G1f：授权 DINOv3 ViT-L/16 的校验、独立缓存、本地 SHA256 迁移、RGB 基线及 D/G/O/S 依赖队列；G1e 等旧组折叠在历史队列。缓存可以按样本边界暂停/继续，训练仍按完整检查点恢复。页面另外读取新引擎力脉冲/悬臂梁原生失败与修正结果、真实视频审计及跨引擎 adapter 实现边界。G2/G3“进行中”代表研发阶段未验收，不等同于此刻有 GPU 训练运行；真实视频尚未加入参数训练，adapter 目前仅原型。控制只作用于注册队列任务；没有每小时自动任务。

支持 8 卡利用率、显存、温度、功耗、CPU、可用内存、磁盘和网速；从项目 `ACTIVE*JOBS.json`、训练 JSONL、验证 summary 和运行日志展示当前轮次、优化步、场预热/联合阶段、验证曲线、训练曲线与最近输出。训练曲线取最近 4 MiB 日志并采样最多约 600 点，显示 10 个采样点的移动平均。GPU 历史保留最近 240 次采集，服务重启后重新积累。

可筛选正式对照、诊断实验和全部实验。页面分别显示场预训练与联合训练；预训练时参数损失不进入优化目标，其参数误差不用于最佳材质指标或早停判断。G1 的真场与置乱真场上界标为特权诊断。ETA 按已完成步骤估算，验证与存盘会影响它。

优化面板展示 G0–G4 的真实状态、验证基准、缓存进度、八组任务队列和最近反馈。G0 通过后准备共享 RGB 特征缓存，随后最多同时运行四组 G1 诊断。六组诊断均完成后，只有真场上界及预测场桥均相对 C 提升超过 2%，且预测场桥优于特征控制，才自动继续全量 C/D；否则暂停投入全量预算，反馈应先修数据或桥结构。这是单种子实验路由条件，不是统计显著性结论。全量任务也可单独点击“继续”明确加入队列。

“暂停全部”阻止新任务启动，训练在完整 epoch 的训练、验证及原子存盘结束后退出并释放 GPU；缓存在单个样本处理完后暂停，G0 验证在当前子任务完成后暂停。“继续全部”恢复队列，单独暂停的实验仍需单独继续。每个实验也可独立控制；继续会加载模型、优化器、随机数与数据加载器状态，在相同 world size 下从检查点接着训练。完成或自动早停的实验不会被继续按钮误重启。页面会区分请求已提交与已经暂停。

停滞规则：G1 联合阶段至少观察 6 轮，连续 4 次验证没有达到 0.2% 的相对改善则自动停止；全量实验连续 5 次。保存 `best_material.pt`、`last.pt` 和停机原因。场预训练连续 3 次验证无有效改善时提前进入联合阶段。瞬时训练 loss 的噪声不作为停机依据。队列只使用空闲 GPU，不抢占其他进程。

控制请求要求本机 Host、匹配 Origin、会话令牌、有效队列心跳及注册实验 ID；SSH 后端再次验证输出路径和动作，写入项目控制文件及审计事件。快照或队列心跳过期时禁用操作。

SSH 失败时保留最后成功快照并标记过期；“运行中”依据记录的 PID 与实际命令匹配，训练记录最后更新时间单独显示。没有远程权限时不会显示伪造数据。日志只读取本项目注册实验，不读取其他用户进程参数、密钥或环境变量。

运行状态和本机 PID 保存在 `runtime.json`，启动输出见 `server.stdout.log`、`server.stderr.log`。关闭浏览器或停止本机服务不会停止 A800 队列。远端队列脚本为 `scripts/optimization_manager.py`，状态文件为 `docs/OPTIMIZATION_PROGRESS.json`；远端 `runs/phase_logs/` 保存子任务日志。若要停止监控，核对 runtime 中的本机 PID 和命令后结束对应 Python 进程。队列管理器停止时先检查日志，避免盲目创建重复管理器；它使用文件锁防止重复实例。
