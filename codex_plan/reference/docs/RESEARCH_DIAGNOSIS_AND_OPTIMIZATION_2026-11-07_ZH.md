# FieldBridge 实验诊断与优化路线

日期：2026-11-07，Asia/Shanghai。正式训练状态复核至 16:18；详细统计快照采集于 16:09。本文依据 A800 实验日志、全量数据审计、当前源代码、论文与 review，以及直接获取的官方项目页面/代码。区分**已测事实、诊断推断、待验证方案**。文中的收益目标不是已实现结果。

## 1. 当前判断与优先级

目标值得继续，但现在尚无证据证明 field bridge 提升了材参推断，更没有“接近在线拟合”的证据。现阶段的首要限制是：**可辨识的物理信息不足、场监督有混杂、反馈结构丢失局部时序，以及验证工程浪费**。单纯更换更大的 backbone 或增加同分布仿真视频，不能解决这些问题。

建议按以下顺序推进：

1. 提高实验效率并修正阶段指标解释；补齐耗时、数据等待、验证进度和 checkpoint 记录。
2. 用真实场诊断上界、类内参数评价和等容量对照，判断旧数据中的场是否确有可利用的信息。
3. 提前实现一个可标定的仿真重放/在线拟合闭环，建立“新动作响应”指标；它不能继续留到研究末期。
4. 生成打破阻尼/类别混杂、包含度量场和已知激励的数据；将预测场改为局部时序反馈。
5. 引入真实数据、独立静态先验与离线拟合教师，扩大未见物体和材质组合覆盖。
6. 在核心消融成立后，再系统比较骨干适配和更强模型。

最终主张应是：**在约定的输入信息、引擎与物体范围内，无在线拟合地预测可迁移到新交互的有效材料参数/分布，显著优于强匹配无 bridge 方法，并在质量—成本曲线上接近充分优化的在线方法。** 静态输入单列为带不确定性的先验估计。

## 2. 实验目前真正说明了什么

### 2.1 正式训练与基线

两组正式实验分别为 `full_giant16_C_aux_no_feedback_seed17` 与 `full_giant16_D_field_bridge_seed17`，各使用 4 张 A800。16:18 两组均到第 2 轮、优化步 1006，正在验证/存盘阶段；只完成第 1 轮验证。总计划 80 轮，前 10 轮是仅优化场预测的预热，随后才是联合材参训练。

| 指标 | C：辅助场监督，无反馈 | D：预测场反馈 | 解读 |
|---|---:|---:|---|
| 首轮 val 标准化材参 MAE | 0.860607 | 0.861308 | 预热期材参头未接受材参监督，不能用于 bridge 优劣结论 |
| 首轮编码场绝对误差 | 0.058046 | 0.058418 | 彩色编码场误差，不是 SI 应力/速度误差 |
| 总参数 / 可训练参数 | 11.474 亿 / 1094 万 | 相同 | 约 99% 参数冻结 |

在**同一份 399 条 val** 上另算了两个诊断：只用训练集全局中位数的 MAE 为 **0.830857**；若额外给予真实本构类别，再使用训练集类内中位数，MAE 为 **0.544621**。后者是特权信息诊断，不能作为部署基线，但它说明：只辨认类别就可能获得很大幅度的总体参数收益，必须评价类内连续参数。

两轮已完成的 240 条工程试跑中，D 相比 C 的最佳 val MAE 分别高约 **1.43% 和 1.72%**；没有观察到 bridge 收益。其 val 仅 14 条，不能据此否定整个方向，也不能将它与全量 val 数值横比。接触平衡损失将 recall 大幅提高，但没有带来参数收益，说明“场指标更好”不等于“物理推断更好”。

目前没有实际引擎重放结果，也没有在线拟合质量曲线。`simulation.py` 只有适配协议、结果校验及标定用例定义，**不等于完成了引擎适配器**。

### 2.2 论文结论和 review 应如何吸收

原论文已使用开放的 DINOv2；需要改进的是时空物理建模和适配方式，不能把贡献写成“首次替换闭源视觉骨干”。

review 中最有价值的质疑是：缺少同样场监督但无反馈的重训对照、物理标定不足、经验应力—速度关系不具有普适性、均值回归风险、静态/部件先验与强逆仿真比较不足。当前工程已设置 C/D 和去除不成立的经验物理约束，这是正确方向，尚需 B/G 与静态先验 E/F。

原文部分指标改善也不等于全面改善：例如 E 的 log 中位误差约 1.901→1.521，但未过滤平均 SPE 约 0.314→0.334，反而更差。因此新版主结果必须保留均值、p90、失败率、逐物体结果和置信区间，不能靠过滤尾部或只选中位数建立主张。仿真回弹更接近某个引擎，也不能替代真实测量来证明该引擎物理正确。

## 3. 当前数据是否足够

**足够做受控的辅助监督/反馈消融，不足以独立支持开放世界手机视频、多材质物体和真实 SI 材参的目标。**

### 3.1 已确认的覆盖与质量

- 全量 4914 个样本包已完成五类数组的 CRC、schema、时间和标签审计，0 个结构失败；HF 归档 SHA 已验证。另有 86 个只有标签而没有 pack 的目录，不属于发布 cleaned split，不能误称为训练时丢弃的失败样本。
- 108 个物体，88/10/10 个 train/val/test 物体；4021/399/494 条。原发布 test 固定。Kaggle V2 已补齐 108 份 Gaussian PLY，结构检查通过。
- jelly/metal/plasticine 为 1598/1619/1697 条，shear/press/stretch/bend/drop 为 945/1012/950/988/1019 条。
- 每个 pack 的数组为 `uint8[3,64,3,224,224]`。当前模型使用 16 帧、3 视角，原视频跨度约 3.99 秒；全跨度均匀取 16 帧可能错过接触瞬间和快速振动，应做 16/32/64 帧以及事件密集采样曲线。

这些检查证明文件可用，**没有证明几何体积、接触力和本构实现已完成物理标定**。Gaussian PLY 并不自动给出真实厚度、内部填充、体积或质量。

### 3.2 四个关键混杂/信息缺口

**A. 阻尼与材料类别完全绑定。** 所有 jelly 使用 `(grid_v_damping_scale=.999, rpic=.35)`，metal 为 `(.9995,.25)`，plasticine 为 `(.9992,.45)`，`substep_dt` 均为 `1e-4`。模型可能用衰减模式辨认类别，再输出类别典型参数。不能把这种收益直接解释为读出了 E 或 rho。阻尼还按步施加，改变时间步而不换算阻尼率会改变物理过程；单独网格衰减对应的等效速率约为 10/5/8 s^-1，但这不等于整个系统的材料阻尼。

**B. 应力场是混有外观的可视化。** 4914 条均设置 `stress_visualization_sh_blend=.35`，没有原始体积应力导出。预测这些颜色可以改善重建外观，却不必理解应力；逐帧归一化也可能消除绝对幅值。旧场应保留为 legacy auxiliary，不能直接用于应力平衡损失。

**C. 有效区域很小。** 审计每 8 帧抽样的前景占比中位数 6.37%，接触占比中位数 0.271%；1084/4914 条在这些抽样帧中接触为零。这可能是释放/跌落、遮挡或未采到瞬间，不能据此宣布视频没有接触。721 条首末光流图完全相同，也不代表全程没有运动。需要补充完整时间轴的事件覆盖、方向/幅值和 mask 审计，避免背景指标主导。

**D. 类别和参数范围相互泄露。** 训练集 jelly 的 E 约 3–15 kPa，plasticine 约 15–180 kPa，metal 约 0.252–12.0 MPa，区间基本分开；这些是当前仿真族范围，不能直接解释为真实金属材料的典型 E。sigma_y 标签仅在 metal 家族存在。必须报告类内 R²、相关性、相对误差，并加入“预测类别→训练类内中位数”的合法基线。

### 3.3 新仿真数据的最小闭环

先选择约 20 个可确认体积/厚度的几何做小型标定集，再扩展规模。每种本构使用分层参数设计，避免完整笛卡尔积爆炸；对关键参数作正交/近正交覆盖，并加入同几何、同外观、同动作、不同参数的配对。

需要同时记录：世界坐标和尺度、质量/体积、相机、物理时间、边界条件、施力/位移控制、反作用力、速度/位移/应变、原始浮点应力及定义、接触法向和摩擦、阻尼率、求解器/网格/时间步与版本。数据生成与渲染随机种子分别记录。

动作优先级：已知位移并测反力的压缩/拉伸、释放后的自由衰减、不同频率的小振幅激励、超过屈服的加载—卸载、不同接触位置的新动作。变化力、几何、尺度、阻尼和相机时要解除与材料类别的固定绑定，同时确保数值稳定。先建立可辨识子集，再添加未知激励的困难子集。

多材质先做 2–4 个可解释部件，分别覆盖粘接、可滑移接触、硬壳—软芯；保存界面条件。把三个不同材料的独立物体放进同一场景，并不能证明支持了粘接复合材料。壳体/薄壁物体应有厚度模型，不能一律作为实心 MPM。

## 4. 当前模型是否足以满足要求

当前模型是一个可用的工程起点，但不足以支撑最终目标，主要问题不在参数总量。

### 4.1 当前结构的限制

1. **大骨干几乎全冻结。** 当前 DINOv2-g 约 11.36 亿冻结参数，可训练约 1094 万；这不等于用十亿级模型学习了材料动力学。先解决输入与反馈，再比较局部 LoRA/后几层适配；与 no-bridge 保持同样适配和搜索预算。
2. **局部物理信息被过早平均。** RGB patch 先做空间平均进入时序/视角 Transformer；场编码最终又对空间及各视角/时间平均。RGB 分支仍有时序信息，但反馈分支缺少“哪里受力、何时发生、如何传播”的明确对应。
3. **低分辨率彩色场不足以表示精细接触。** 16×16 特征上采样至 112×112 不会凭空恢复接触边界。contact/彩色 flow/彩色 stress 共 7 通道，不是度量运动或应力张量。
4. **三固定视角没有相机几何建模。** 当前 view dropout 为 0，不能用训练三视角结果证明手持单目可用；相机运动和物体变形容易混淆。
5. **一个全局参数向量无法描述复合物体。** 单高斯 logvar 也不自动给出校准良好的不确定性，更不能表达多个同样合理的参数解。
6. 静态 prior 接口已存在，但当前没有实际独立先验输入。不能把尚未运行的 E/F 写成已验证模块。

### 4.2 推荐结构演进

**第一步：保持可比较性。** 先用相同 RGB backbone 和预算完成 B/C/D/G：直接回归、辅助场监督无反馈、语义场反馈、等容量普通特征反馈。增加 oracle 真场反馈与场置乱诊断；oracle 只用于训练/验证诊断，不能进入部署主结果。

**第二步：局部时序桥接。** 预测带置信度的接触、位移/速度、形变梯度等场 token，保留位置、物理时间、相机信息；用局部时空 cross-attention 把接触区域和邻域响应反馈给参数 token，避免将全部场压成平均向量。多尺度解码，并测试接触事件附近密集帧与长时间稀疏帧结合。字段缺失时显式 mask，置信度低时减小反馈。

**第三步：独立静态先验 + 动态残差。** 从首帧/重建得到部件类别、刚度范围和先验分布，动态场更新这个分布。静态先验来源不能读取同一物体真值；训练集内部用 out-of-fold 预测，记录先验来源与置信度。E/F 在相同先验下比较反馈增益。若静态先验用了文本/深度/三维资产，分组报告。

**第四步：有效参数和部件化。** 输出引擎/本构条件化参数；E、rho 和适用的屈服参数为正，nu 满足所选本构稳定域，未激发屈服时输出范围/下界或缺失标识。先做全局→2–4 部件，再考虑密集连续材料场。用校准集、ensemble/覆盖率和 OOD 检测验证不确定性，而不是仅检查一个 95% 覆盖数字。

**第五步：响应监督与摊销逆拟合。** 对训练物体离线进行多起点拟合，保存多个合理解、置信度与新动作响应；训练学生预测参数/分布，加入经过标定的 rollout 或响应蒸馏。主要推理仍无迭代，少量在线修正另作 O+D 组。教师最优解不是唯一物理真值，不能将教师伪标签当作真实测量来证明准确性。

## 5. 与其他方法相比是否有优势

目前只能提出**待验证的优势假设**：field 将辅助物理监督变成显式可检查的中间表示；静态先验加动态更新可能提升真实物体泛化；离线学习摊销多个物体的拟合成本，使无在线迭代预测在新交互上接近优化方法。当前结果尚未证实这些优势。

## 6. 仿真引擎怎么选，容易踩什么坑

先重放并标定原引擎，以避免同时更换数据、模型和评估引擎导致归因混乱。并行做一个小规模候选引擎比较，但不要先批量生产新数据再检查物理。

| 候选 | 适合任务 | 采用前必须验证 |
|---|---|---|
| 原 MPM 路线 | 旧数据重放、较大形变/塑性、保持已有本构含义 | Gaussian→体积粒子、边界和实际动作、阻尼/时间步、应力单位及定义、质量守恒、网格锁定/耗散 |
| [Newton 多材料 MPM 示例](https://github.com/newton-physics/newton/blob/main/newton/examples/mpm/example_mpm_multi_material.py) | GPU 新数据生成、多种粒子材料属性 | 示例支持材料属性不等于已验证粘接复合界面；检查可用梯度、求解稳定性、参数含义与可复现性 |
| [libuipc](https://github.com/spiriMirror/libuipc) | FEM、壳/杆与刚体耦合、稳定接触，适合壳体/部件参考 | 可微接口仍在发展，不能预设完整端到端自动微分；需要时先用黑箱/有限差分拟合，或换已验证梯度接口 |
| [Boba](https://github.com/jianxiapyh/Boba-Public) | 大量候选弹簧参数的批量 rollout、响应教师 | 弹簧离散化/网格依赖，不能直接把 k 当 E；确认批次约束、可微范围和渲染是否主导耗时 |

最小标定包括：单轴力—位移、小应变悬臂、自由振动衰减、跌落接触、质量—体积、时间步/网格收敛、穿透检查、两材料界面。先用 8 个标定场景得到可复现实测曲线，再决定哪些物体/本构值得扩展。

不同 solver 预测同一物体得到的参数可以不同；应比较新动作的响应并标明 `theta_eff(engine, geometry, boundary)`，而非要求未经映射的参数数字一致。跨引擎验证有助于发现教师/学生共同利用了某个引擎缺陷，但不能代替真实测量。

## 7. 目标本身是否合理

在限定输入与材料族的条件下，接近在线逆拟合的**响应质量**是合理且有价值的研究目标。对任意现实物体、静态无尺度 RGB 同时唯一恢复 E、nu、rho、sigma_y，则一般不可辨识。

- 静态外观可以提供材料和结构先验，不能唯一决定连续物理常数；塑料外壳厚度、空腔、泡沫密度、复合填充均可能不可见。
- 未知力的准静态变形中，施力与刚度可共同缩放；仅看变形难以分开。
- 动态视频提供更多信息，但刚度、密度、几何尺度、阻尼和边界仍会混淆；自由落体本身并不能测出密度。已知质量/体积、尺度和力/激励可打破部分歧义。
- 没有塑性激发时，屈服应力通常只能给约束范围；nu 在缺乏横向/体积形变时也可能很弱。
- 参数等价不妨碍在某些动作上获得相似响应，但不能由同一拟合视频的漂亮重渲染宣称跨动作理解。

建议分三个任务报告：A 静态输入→先验范围与校准；B 短动态 RGB、尺度/动作按协议可得→有效参数和新动作响应；C RGB-D/质量/已知力增强→更强物理识别。手机演示从 B 的受控版本开始，再逐步降低额外信息需求。

开发目标沿用：相对最强匹配 no-bridge，新动作响应误差降低约 30%；与同信息充分优化方法差距约 10% 内。这是阶段性方向，非保证。必须有三种子、成对物体 bootstrap、未过滤尾部和成本曲线；当前仅 10 个测试物体，统计外推有限，需要外部更多未见物体测试。

## 8. 训练效率、工程陷阱与可执行优化

### 8.1 已定位的开销

首轮每组训练约 5 分钟，验证约 15.5 分钟，首轮总周期约 20.6 分钟；这些来自日志阶段时间，为粗粒度测量，不是 CUDA profiler 分解。约四分之三的周期花在验证。后续缓存、训练阶段和系统负载会改变耗时，不能据此给出精确 80 轮 ETA。

代码确认：训练 BF16，但 `evaluate()` 仅 rank0、batch=1、DataLoader 默认 workers=0、没有 autocast/pin_memory；另三卡先到集合通信等待。100% GPU utilization 配合约 80–90W 低功耗，可能是 NCCL 等待/忙轮询，不能当作有效矩阵运算饱和的证据。GPU 显存快照约 6.1 GiB/卡，也提示可以研究更合理批次，但低显存本身不等于低计算利用率。

每读取 NPZ 的一个数组，需解压完整 64 帧，再选 16 帧；两组、每个 epoch 重复处理。同机单线程的 3 样本 CPU 加载测量为 0.944/0.748/0.763 秒；样本少且缓存状态不受控，只用于定位，不是整个数据集吞吐结论。

### 8.2 优化顺序与验收

| 优先级 | 改动 | 原因与验收 |
|---|---|---|
| P0 | 全 rank 分片验证，BF16 与 batch/workers/pin_memory 参数化 | 第一优先级；合并逐样本结果后计算全局指标，覆盖 399 条且 ID 无重复/遗漏；先对同 checkpoint 做 FP32/BF16差异检查 |
| P0 | 分阶段计时、val 每 N 样本 heartbeat、样本/秒与等待时间 | 区分解压、H2D、前向、反向、通信、val 和存盘；进度停在 step 不代表训练挂死 |
| P0 | 预热/联合分开选 best checkpoint | 预热期材参头未接受材参监督，当前代码仍按参数 MAE 更新 best；新增 best_field 和仅联合阶段的 best_material，避免把随机预热头作为正式模型 |
| P0 | checkpoint 先后顺序与超时 | 当前非主卡等待 rank0 验证，通信超时 30 分钟；慢 AFS 可能导致损失整轮。将完成训练的状态可靠落盘，分布式验证后原子提交正式状态，避免把半轮标成完成 |
| P1 | 预处理 selected frames 为分片/可 mmap 格式，或缓存冻结 patch features | 避免每轮全视频解压和冻结骨干重复前向；记录 cache key、数值误差与失效条件 |
| P1 | 测 batch=1/2/4 与 1/2/4 GPU 的 time-to-target | 目前每组有效 batch=8；batch2×4卡、accum1 与 batch1×4卡、accum2 相比可减少 microstep/通信，但需保持成对公平和重新核对 LR |
| P1 | 合并 masked loss 分母通信，降低每步同步与日志开关销 | no_sync 只避免部分梯度同步，损失中的 all_reduce 仍在；保持全局 valid-label 归一化，避免缺失 sigma_y 的 rank 权重错误 |
| P2 | 学习率 warmup/cosine、联合阶段验证节奏、早停 | 当前固定 LR；以同预算寻找达到质量门槛的最短时间，不是仅比较最后一轮；不以尚未训练的参数头早停 |

若仅将约 15.5 分钟的验证理想分到 4 卡，周期可由约 20.6 分钟降到约 8.9 分钟，即约 2.3 倍的理论周期改善；实际受 AFS、解压和负载限制，必须实测，不能承诺。AMP/worker/cache 的收益另行做消融，避免重复相乘夸大加速。

**分布式验证陷阱：** 默认 DistributedSampler 会补齐样本造成重复；不能把重复记录计入指标。使用不补齐的 shard，或按 sample_id 严格去重且核对集合。不同 rank 样本数不同时避免每步同步的 DDP forward，最后统一合并。不能直接平均各 rank 的 MAE，尤其 sigma_y 有缺失标签。

**日志陷阱：** 当前记录的是 rank0 最后一个 microbatch 的分项，不是全 rank、完整 accumulation 的均值；`.item()` 和逐条 CPU 拷贝还会触发同步。用累计 numerator/denominator 每 10–20 step 汇总，注明 train/val 指标定义，写入独立计时字段。

**并行加载陷阱：** val 先测每 rank 2/4 个 worker 和小幅 batch 增长，设置合适的 prefetch/persistent worker，限制每 worker 的 OMP/MKL 线程。两组各四 rank 同时读取 AFS 时可能出现带宽、元数据或解压竞争；worker 越多不保证越快。先记录热/冷缓存条件下的吞吐和 CPU 占用，再决定是否将选帧数据放在本地分片或共享 page cache。独立采样 GPU profiler 时限定步数和开销，避免在八卡正式训练上另起竞争性的 GPU 作业。

**checkpoint 陷阱：** 当前保存整个冻结骨干，C 组实测 last/best 文件均为 4,677,638,867 字节，约 4.68 GB/份。冻结骨干可改为固定来源和 SHA，加可训练权重、optimizer、RNG、codec、manifest、source hash 的增量 checkpoint；加载时严格拒绝不匹配骨干。若有 LoRA/解冻权重，必须保存实际可训练变化。

**缓存容量与一致性：** 全数据、3 视角、16 帧、1536 通道、16×16 patch 的 FP16 缓存约 **172.8 GiB**，不应直接塞进只剩约 188.9 GiB 的根盘。16:18 AFS 的 statvfs 快照约余 3.20 TiB（共享挂载可见容量，不代表独占配额），主机可用内存约 930 GiB，可考虑分片 mmap/共享 page cache；8 进程各自完整复制会超过 1.3 TiB。缓存应位于 trainable projection 之前，只缓存 RGB 派生特征；key 包含骨干 SHA、图像归一化、分辨率、frame indices 和精度。改变像素增强、骨干 LoRA/解冻后必须失效，不能复用旧特征。

**复现陷阱：** 更改 worker/persistent worker、随机采样、视角 dropout、batch/world size 都可能改变随机序列。旧代码“同 world size 的 epoch 边界恢复”不能自动扩展为任意新管线的逐步完全复现。效率改动作为 v2 成对运行，记录 resume 来源与差异；原正式训练保持其版本定义。

### 8.3 效率验收目标

先做固定 checkpoint、相同样本的短 benchmark，而不是重启多个 80 轮训练。记录端到端 wall time、样本/秒、峰值显存、GPU 功耗、数据等待占比和验证集合完整性。争取将验证占周期比降至 25–30% 以下、数据等待降到 step 时间 20% 以下；这是优化目标，视实测再调整。

预处理/缓存的构建时间、空间及摊销回本轮数也要报告。若解冻 backbone 后缓存不能用，需重新计算 time-to-target。主指标是获得可靠结论需要的总 GPU 小时和墙钟时间，而非把 nvidia-smi 利用率填满。

## 9. 下一阶段实验清单与反馈节点

### G0：效率与可靠性

交付验证/训练耗时分解、分布式验证一致性、阶段 checkpoint 选择、cache 小样本 benchmark、GPU 数/批次曲线。反馈包括实际加速和数值变化；未通过 ID 覆盖及指标一致性检查，不扩大训练。

### G1：先判断旧场是否值得继续

使用固定的约 512–1000 条 train 诊断子集和物体隔离 val，完成真正的联合阶段，比较：RGB、RGB+真实场诊断上界、RGB+预测场、置乱场、等容量普通特征反馈；增加 64 样本过拟合检查和类内参数指标。所有正式基线仍保留原 test，不用 test 做方向筛选。

若真实场上界没有稳定收益，优先修数据/激励/度量场；若上界有收益而预测场没有，优先修场预测与局部时序桥；若 G 与 D 同样好，不能声称收益来自物理场语义。选择明确的最小实用改善门槛并用重复种子检查，不只看一次最佳点。

### G2：打通仿真闭环与小型标定数据

实现一个实际 engine adapter，先通过 8 类标定，再对约 20 个几何产生可辨识训练与新动作验证。实现简单但充分优化的黑箱/可微逆拟合基线，输出预算—响应误差曲线。这个阶段就暴露几何/尺度/边界无法对齐的问题，避免等模型全部训练后才发现无法重放。

### G3：新数据 + 局部场 + 静态先验

训练数值场、多采样时间、局部反馈模型；独立引入 PIXIE/VoMP 或开放替代先验，做 E/F；Deform360/PokeFlex 做真实运动自监督与响应验证。先完成统一 schema 和小样本闭环，再增大下载和训练量。

### G4：强对照与结论

固定模型与超参后，完成 B/C/D/G/E/F 三种子，PhysTwin/EMPM/适配的 MatPhys 等在线曲线。分别报告纯 RGB 与信息增强组。最终结论依据未见物体/新动作响应、尾部、置信区间和总成本；若仅初始化加速有效，则准确表述为 O+D 的系统收益，而非零在线拟合达到同等质量。
