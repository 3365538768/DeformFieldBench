# 无空闲机器期间：最小算力执行协议

更新：2026-11-09。用户明确表示当前没有空闲机器，要求继续优化方案。因此训练、仿真、下载权重、SSH 监控与远程扫描均保持暂停；本文为后续可用资源准备，不是已经启动的队列。内部日期目标会随资源释放调整，不以牺牲证据质量强行承诺 11 月 15 日前全部完成。

## 1. 先准备材料，不从头重训

恢复资源后的第一步是一次性取得必要回执和少量小文件，不先全量复制数据/检查点，也不做高频监控。需要的最小清单：

| 材料 | 最低字段/内容 | 为什么会阻断结论 |
|---|---|---|
| 原稿版本 | PDF SHA、修订时间、表号/数值 | 避免对错误版本做 rebuttal |
| 原 full 与 supervised 的运行配置 | CLI 覆盖后的配置、日志头、环境版本、实际阶段起止 | 公开 JSON 候选彼此不同，不能认定实际匹配 |
| 原 checkpoint | 路径、SHA、模型结构与配置、保存 epoch、选模依据 | 先确认可复算，避免训练后才发现版本不兼容 |
| 小型预测产物 | 每样本 ID、对象 ID、GT/预测、mask、本构、样本状态、seed、split | 有它即可在本地做大部分指标/散点/常数控制，无需 GPU 重推 |
| replay 回执 | 同一对象/动作/初态/相机、参数与非预测 nuisance、评估帧范围 | 判断是否同条件、是否真正未来预测 |
| 数据 manifest/split | 原 ID 到对象/pack/本构/动作映射、缺失与排除清单 | 解释 4914/108 与 5000/100 口径，而不是偷偷改 split |
| 原仿真设置 | 引擎 revision、dt/输出时刻、网格/粒子、单位、阻尼、接触、actuator | 定位低回弹与物性可辨识性 |
| VLM 回执 | model/version、prompt、帧/视角、解析配置、原始输出与失败数，移除密钥 | 补真实运行身份，避免从默认 tag 猜测 |

当前本地可搜索路径尚未发现足够的原论文逐样本预测与运行回执；这仅是本地范围的结果，不等于远端文件不存在。已知 Git 历史可提供实现，但无法提供训练事实。

没有上述材料时，正式记录为“原稿不可完整复核”；后续可做标注清楚的重新实现，不能称原稿精确重现。

## 2. 三层算力预算与顺序

### L0：本地、无需模型

已经完成 review 一致性核验、固定历史源码审计和来源索引。现在先冻结：控制矩阵、主要统计单位、参数变换、样本失败处理、V2 触发规则、评估所需字段和回复工作稿。

如取得已有预测表，先完成以下本地分析，再决定任何 GPU 重推：

- 复算论文 Table 1；列出逐项差异，不只比较一个总分。
- 全样本/逐材料族散点、常数与类别先验、族内相关和预测方差，判断连续参数是否发生塌缩。
- 按对象宏平均、尾部误差和失败率；分析 replay 与参数误差是否一致。
- 检查重复对象、视角和派生样本是否跨 split；确认训练统计不读测试标签。

**L0 即可能触发修正文稿，但缺少严格匹配训练结果时不宣布 V1 无效。**

### L1：有少量资源，先做评估和开关检查

1. 先一个样本的 checkpoint 加载/预测，与原预测表核对；再对固定 validation 做一次完整评估。先修复模型版本、归一化和帧采样，不急着训练。
2. 记录一次实际 decode、H2D、forward 和峰值显存；不能在未测量时承诺训练需要几小时。
3. 检查 C/D 的计算图控制，先用少量训练样本验证：字段/监督/原始输入相同，唯一信息差异确实是待研究的反馈。
4. 原 MPM 用最少的两个算例定位单位与材料响应，再加 release/drop。只做必要轨迹导出，延后高分辨率全视频渲染。
5. 外部 baseline 每个先一个验证资产，能输出可信单位、合法形状与缺失维度 mask 后，再安排完整评价。

这层 smoke 的效果数字不计论文结果。不能用 20 条过拟合或 head-only 快速诊断替代 reviewer 要求的完整重训。

### L2：资源允许后，才跑会改变结论的训练

按优先级依次安排：一个完整、匹配的 C/D seed → 检查异常和验证效应 → 其余两个 seeds/已冻结的正式测试与必要比较。原 D 的训练回执若完整且完全符合协议可复用；否则不能把旧 best 值与新 C 直接比较。

能共享的只有反馈尚未影响学习的阶段。原代码默认为 flow+force 100、stress 80、joint 100、param 40 epoch：前两阶段仅在种子/参数初始化、数据顺序、冻结状态和训练目标确实相同时可以共享；**joint 已涉及参数链和反馈，必须 C/D 分开**。最后 param 阶段虽然便宜，但只重训它只能评价固定 decoder 下的 head 学习，不是完整系统消融。

若资源只够一个 seed，报告为 preliminary，不以 bootstrap 自动补成三种子证据。不因第一 seed 表现好就提前宣布成功，也不因一次负面波动宣布原系统无效。预算上限到达后停止并如实报告不确定性；不自动开启模型/损失/数据的大范围搜索。

## 3. 比“关掉反馈”更精确的开关定义

固定历史 `logic_model/model2.py` 有多种参数链模式，不能按新重构模型的开关想当然移植。恢复时需导出实际启用模块及张量路径，确定以下三类输入：

1. **Bottleneck 特征 `z_phys`**：C/D 始终保留，不改变编码器或其监督。
2. **预测 stress/flow/force 编码到参数头的输入**：这是核心 C/D 唯一要移除的信息；C 在训练与测试始终用样本无关占位，保留融合形状，D 使用预测值。所有 strong-param token 分支也需遵循同一规则。
3. **可选 shared decoder latent (`shared_field_param_feat`)**：它不是预测场图本身。研究“显式预测场图反馈”时，两组保持其原设置一致并披露；如果要研究“所有场解码器信息反馈”，需另设变体同时去掉它。不能一次去掉二、三类后仍声称只检验预测图反馈，也不能保留它而声称完全没有任何场分支特征。

从论文定义确定主问题后冻结 C 的精确定义；不要在结果出来后选择更有利的消融命名。保存开关及差异清单，检查未通过 class head、skip connection 或 GT 替换重新传回信息。

## 4. 新增的原实现陷阱：mask、GT 场与静态几何

本轮进一步读源码发现以下**待核实风险**，不代表已发现论文实际泄漏：

- `logic_model/train.py:_forward_model_batch` 为 `LogicPhysModel2` 传入 `object_mask=object_gt`；该 mask 可进入 stress 融合与参数场编码。要核对原评估是否也这样使用。若 GT mask 参与推断，它是额外输入，不能直接称纯 RGB-only。原稿复算可保持其原条件并披露；部署另列统一预测 mask，不要为了“公平”只改变某一个组。
- 最后 param 阶段支持 `param_field_source_mode=mixed_gt_pred` 和 `param_gt_field_ratio`。源码默认 ratio=0，主配置未显式启用，但实际运行需由 resolved config 核实。测试不得依赖 GT stress/flow；oracle 另列。
- `shared_field_param_encoder` 是可选旁路；是否启用取决于实际结构，不从名称推断。
- 几何残差、patch token 与多视角输入均可能影响效果；只缓存 pooled DINO features 不能复现需要 patch token/像素 stem 的原模型。
- `TypeError` 被 forward wrapper 捕获后可能回退到较少参数的调用；恢复时要校验实际分支，避免把模型内部真实错误误认为接口不支持。

这些检查先在本地来源清单里登记；不能在未看到论文实际回执时就宣称存在数据泄漏或原结果无效。

## 5. 独立 baseline 与写作如何压缩时间

PIXIE/VoMP 优先用公开预训练权重，不为 rebuttal 从头复现其全部预训练。单列“外部预训练静态资产先验”，不能把 zero-shot 与本项目监督结果差距当桥接因果证据。若增加同数据适配，固定 train/val 调参预算，结果与 zero-shot 分开。

AutoPhyX 先核验 checkpoint 和接口，遇资源缺失设工程时限；OmniPhysGS 按其生成优化目标做明确标注的有限行为比较，不能花数天把它改造成另一种 inverse-video 方法后仍称官方基线。

真实 5 段优先重用原视频和对齐资产，补共同可见区域可视化及控制，不在本轮临时承诺采集带力传感器的新数据。有标定数据才能评真实材参，只有 replay 就诚实写行为级验证。

写作不等待所有训练结束：现已提供 [工作稿](REBUTTAL_RESPONSES_WORKING_DRAFT.md)，先完成事实、定义、控制差异与限制；表格缺失字段显式保留。最终只把已经完成的结果填进去，不将 anticipated results 写成结论。
