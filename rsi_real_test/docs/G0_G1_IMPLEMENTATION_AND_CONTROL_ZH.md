# G0/G1 优化执行与控制说明（2026-11-07）

## 已落实的执行顺序

1. 旧全量 C/D 在各自第 3 个完整 epoch 的 `last.pt` 原子落盘后安全退出，保留原始检查点和 v1 代码/配置备份 `docs/engine_v1_before_g0.tar.gz`。日志中少量第 4 轮步骤不代表已保存第 4 轮，不从这些步骤恢复。
2. G0：运行 CPU 行为契约测试；固定同一旧 C 检查点、同一批 64 个验证样本，对比原串行 FP32、四卡 FP32、四卡 BF16。覆盖与误差门槛通过后才启动后续任务。
3. G1：冻结 512 train / 128 val 的物体隔离诊断清单，排除测试集，只由训练集拟合参数标准化统计。先生成共享 RGB 冻结特征缓存并检查实际样本的推理一致性，再最多四组并行训练。
4. G1 反馈后决定是否继续全量 C/D。G2 引擎标定、G3 数据/桥结构、G4 多种子与强方法对照当前只列为计划，网页不会将它们显示为已实现。

|---|---:|---:|---:|---:|
| 单卡 FP32，batch 1，workers 0 | 152.034 秒 | 1× | 0 | 0 |
| 四卡 FP32，batch 2，workers 2 | 约 30.44 秒 | 4.994× | 1.87e-10 | 2.53e-7 |

这组耗时包括验证的数据加载、前向和结果汇总，不包括各进程模型初始化；不是整个训练任务的加速比。三组样本 ID 完全一致。CPU 测试还覆盖了验证样本数不能整除进程数、以及样本数小于进程数的情况。

完整证据：`docs/G0_BENCHMARK.json`，三个子任务的 `runs/g0_benchmark/*/summary.json` 与 `predictions.jsonl`。14 项 CPU 测试复核通过（22.77 秒），日志 `runs/phase_logs/g0_tests_recheck.log`。测试验证了暂停恢复后的模型权重与连续训练一致、平坦验证指标触发早停并保留最优权重、缓存输入一致性以及部署模型拒绝真场输入。

部署后核验：640 条缓存用时 517.15 秒，共 14.39 GiB；4 条真实样本的最大预测差为 0。C 在第 3 轮、192 步通过网页单独暂停；全局暂停时其余任务分别保留完整检查点，八张卡训练显存降为 0。使用 C 的真实紧凑检查点再次独立评估全部 128 条验证样本，唯一覆盖 128、重复 0，与训练内验证 MAE 差为 0；检查点大小 32,336,009 字节（约 30.84 MiB）。

## 六组诊断和预期反馈

各组使用相同 DINOv2 ViT-S 冻结骨干、相同模型模块/参数容量、数据、seed 17、batch 4 × accumulation 2、最多 24 轮。前 2 轮为场预训练预算，随后联合训练；RGB-only 组关闭场损失，预训练预算内没有有效场监督。小模型用于快速查明信息与桥的有效性，不能替代后续 A800 上大骨干的正式对照。

| 组别 | 反馈输入 | 用途 |
|---|---|---|
| B_rgb_only | 无 | 不使用场监督和场反馈的基线 |
| C_aux_no_feedback | 无 | 只增加场辅助监督，隔离辅助任务收益 |
| D_field_bridge | 预测场 | 目标部署方法，判断桥是否有额外收益 |
| G_feature_control | 同通道数视觉特征 | 排除额外参数与特征路径的收益 |
| O_oracle_fields | 真场 | 特权诊断，判断现有场标签的信息上界 |
| S_shuffled_oracle | 同 split、不同物体的置乱真场 | 特权诊断，排除任意场分布/统计捷径 |

真场只通过显式的诊断入口进入 O/S；B/C/D/G 入口拒绝真场。共享缓存仅由 RGB 编码得到；场标签另存为监督目标。缓存绑定清单 SHA、官方骨干 SHA、编码实现 SHA、时间/视角/尺寸/精度；暂停后可跳过已完成样本。正式发布缓存前对真实 train/val 各两条样本做原 RGB 与缓存预测的一致性检查，并核对监督目标、掩码和时间完全一致。

完成六组后，按联合阶段最优验证 MAE 自动写 `docs/G1_DIAGNOSTIC_RESULTS.json`。仅当 O 和 D 均相对 C 提升超过 2%，且 D 优于 G，才自动继续全量 C/D；否则保持全量任务等待并提示优先修数据或桥。此门槛用于预算分配，单种子小样本结果不构成显著提升、物理正确性或接近在线拟合的证据。

## 早停、暂停与继续

- 联合阶段至少观察 6 次完整验证。G1 连续 4 次、全量连续 5 次没有达到 0.2% 的相对改善，则停止该实验，保留 `best_material.pt` 和 `last.pt`，记录 `validation_material_plateau`。微小噪声不会无限刷新耐心计数。
- 场预训练连续 3 次没有实质改善，则提前结束预训练并进入联合阶段；不以尚未训练的材质头误差停止整个实验。
- 网页支持暂停全部及单独暂停。训练完成当前完整 epoch 的训练、验证及存盘后退出并释放 GPU；缓存完成当前样本后暂停，G0 当前验证子任务完成后暂停。页面显示“等待本轮检查点后暂停”直至实际退出，因此按钮不是立即强杀。
- 继续时恢复模型、优化器、各 rank 随机数和数据加载器生成器。保持 world size，不从不完整 epoch 假装精确恢复。验证前先保存恢复点；若验证中断，恢复时重做验证，避免重复训练已完成 epoch。
- 完成或自动早停的实验不会被“继续”误重启。全量任务的“继续（排队）”属于手动启动请求，仍等待足够空闲 GPU。

## 工程变化与可观察性

- 完整验证由各 rank 按无填充分片并行执行，汇总后严格检查 ID 唯一覆盖，避免 DistributedSampler 为补齐样本而重复计分。仅 rank 0 写最终结果。
- 新日志提供跨 rank 的损失均值、数据等待、训练/验证/整轮时间、各 rank 验证进度和停滞轮数。场预训练指标与联合阶段最优材质指标分开。
- 冻结骨干从紧凑检查点移除，记录官方权重校验值；恢复时重新载入并检查缺失键。tiny 随机测试骨干仍完整保存，避免随机重建破坏恢复一致性。
- 队列管理器持有文件锁，每 2 秒写心跳，保留子任务日志与事件；只使用空闲 GPU。网页每 15 秒采集、每 5 秒显示本机缓存。
- HTTP 控制仅监听本机，核对 Host、Origin、会话令牌、快照与管理器心跳；远端再验证注册 ID、动作与项目输出路径。控制通过 JSON 输入和原子控制文件执行，并写审计事件。
